# Echo

Telegram-бот для поиска **возможных публичных совпадений никнейма** через Sherlock и Maigret. Объединяет результаты с сохранением исходных статусов, показывает источники описаний площадок, поддерживает отметки и заметки, HTML/PDF/CSV/JSON и шифрование age. Интерфейс: русский и английский. Бренд настраивается через `ECHO_BRAND` (по умолчанию **Echo**).

Раздел «Инструменты» подключает шесть работающих модулей: ExifTool, Tesseract OCR, ZXing-C++ QR, паспорт сайта с WhatWeb/DNS/TLS, извлечение страницы Trafilatura и варианты собственного домена dnstwist. Есть рабочие папки, сравнение собственных проверок и ZIP с SHA-256 manifest и age. Новые модули не вызывают DeepSeek. Личный кабинет показывает настройки, задачи и занятое место; оплата и баланс не реализованы.

Наличие одинакового ника не устанавливает личность, принадлежность аккаунтов одному человеку или его активность. Бот не использует утечки, закрытые профили, Tor, обход CAPTCHA, извлечение скрытых контактов и автоматическое расширение поиска.

## Запуск

Нужны Docker Engine/Desktop с Linux containers и Docker Compose v2.20+, Linux kernel с Landlock ABI ≥3 и seccomp, исходящий HTTPS/DNS, Telegram Bot Token и строка подключения PostgreSQL. Для eco ориентир — сервер с 4 ГБ RAM и местом для образов и данных. Домен, веб-сервер и входящие порты не нужны.

```powershell
Copy-Item .env.example .env
# Отредактируйте .env: ECHO_BOT_TOKEN и ECHO_DATABASE_URL.
docker compose up -d --build
docker compose ps
```

Linux/macOS: `cp .env.example .env`, затем те же команды Docker. В `ECHO_DATABASE_URL` вставьте готовую строку провайдера: `postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require`. Также поддерживаются `postgres://…` и `postgresql+asyncpg://…`; SSL-параметры обрабатываются драйвером. Спецсимволы в логине/пароле должны быть закодированы в URL. `.env` не хранится в Git. Бот не запускается без токена.

Миграции выполняет отдельный сервис `migrate`. `bot` использует polling, `worker` обрабатывает общую очередь и каталог. По умолчанию подключается ваша PostgreSQL по строке из `.env`, Redis запускается без опубликованного порта. Локальная PostgreSQL доступна отдельно через профиль `local-db` ([инструкция](docs/deployment.md)). Контейнеры приложения непривилегированные, с файловой системой только для чтения, временным tmpfs и общим файловым volume. В eco одна тяжёлая задача на весь deployment, оба поисковых движка выполняются последовательно. Для standard: `docker compose -f compose.yaml -f compose.standard.yaml up -d --build --scale worker=2` на сервере с достаточной RAM; [бюджет ресурсов и ограничения](docs/modules.md).

DeepSeek **не обязателен**. Для подключения достаточно API-токена `ECHO_AI_KEY`: адрес сервиса и модель уже заданы внутри приложения, в `.env` их указывать не нужно. Для разрешения обращений задайте `ECHO_AI_ENABLED=true`; пользователь отдельно включает AI в `/settings`. `ECHO_AI_INTENTS=false` по умолчанию. Для денежного учёта дополнительно задайте оба тарифа за миллион токенов и дату их проверки; без них действуют проверяемые ограничения числа запросов и максимального вывода.

## Использование

1. Откройте личный чат и отправьте `/start`. Выберите цель: «Проверить свой ник», «Проверить свой сайт» или «Обработать файл». Для поиска отправьте собственный ник.
2. Выберите Sherlock, Maigret или оба; покрытие и AI-описания. Нажмите «Начать».
3. В одном сообщении обновляются состояние и фактические счётчики. «Показать готовое» открывает текущие результаты, «Остановить» отменяет задачу.
4. `/tasks` → выдача с пагинацией и фильтрами → карточка: ссылка, CopyTextButton, основание, отметка и заметка.
5. Скачайте отчёт. Для `.age` сначала добавьте **публичный** `age1…` ключ в `/settings` и подтвердите его SHA256 fingerprint перед отправкой.
6. `/delete_my_data` с явным подтверждением удаляет ваши данные. История по умолчанию выключена: результаты истекают через 6 часов; включённая история — через 30 дней, оба срока настраиваются.

`/menu` → «Инструменты» → модуль → ввод → подтверждение → задача → результат/экспорт. `/folders` создаёт папку для выбранных карточек, отчётов, загруженных файлов и заметок. «Сравнить» в выдаче или `/compare` позволяет выбрать две собственные завершённые проверки одного типа и цели. Владение/разрешение подтверждается вручную.

Из QR можно перейти к паспорту сайта, из паспорта — к извлечению текста, из метаданных — к очищенной копии. Каждый переход показывает ввод и требует подтверждения. Для одинаковых проверок своего ника и URL предлагается открыть собственный результат за последние 30 минут либо подготовить новый запуск. Учитываются тип инструмента, параметры и срок хранения; чужие результаты не используются.

В поисковой выдаче есть пояснение охвата и кнопка «Что проверено и что осталось». Блокировки, таймауты, отсутствие совпадения и неизвестный охват разделены; каждый движок считается отдельно. «Выбрать несколько карточек» позволяет отметить до 50 результатов, выбрать или создать папку и сохранить подборку целиком. При превышении вместимости ничего из подборки не записывается. После сохранения видны названия материалов и срок хранения.

«Ошибочное совпадение» в карточке теперь предлагает причину: общая страница, другой ник, недоступный профиль или другая причина. Это личная отметка с временем, отдельная от исходного ответа движка. Причины, заметки и охват включены в JSON/HTML/CSV/PDF; в HTML есть фильтр личных отметок. Сохранённые ранее папки остаются снимками на момент сохранения.

Команды: `/start`, `/menu`, `/tools`, `/folders`, `/compare`, `/account`, `/help`, `/search`, `/tasks`, `/settings`, `/privacy`, `/delete_my_data`, `/about`, `/cancel` (отмена текущего ввода). `/admin` доступен только ID из `ECHO_ADMINS`.

Текстовые действия работают без AI: «Покажи игровые сайты», «Только ошибки», «Скачать PDF», «Остановить поиск», «Повторить неудачные проверки». Неоднозначные AI-intents превращаются в кнопки подтверждения; модель не выполняет действия сама.

## Покрытие и ограничения

- Sherlock **0.16.2**, Maigret **0.6.6**, Python **3.12**; движки и локальные инструменты в отдельных virtualenv. Python-зависимости закреплены в `uv.lock`, `engines/*/requirements.lock` и `tools/requirements.lock` с хэшами.
- «Основные площадки» — реальный ограниченный список доменов; «100 площадок» — первые подходящие записи Sherlock и рейтинг Maigret, без обещания одинакового состава или скорости. «Расширенное» — до `ECHO_MAX_SITES` подходящих площадок на движок.
- Один движок проверяет площадки последовательно, чтобы применять распределённый интервал запросов к хостам. В eco последовательны также движки и задачи. Большое покрытие может не уложиться в таймаут: сохранённые результаты выдаются как PARTIAL.
- Исключены Tor/I2P, отключённые записи Maigret, зеркала, неточные совпадения, активация токенов и TLS impersonation. Состав пригодных площадок меньше исходных баз. Обхода защиты нет.
- Подтверждение совпадений опирается на правила движков. HTTP 200 сам по себе ничего не подтверждает; 403/429/5xx и известные перенаправления понижают результат. Недоступные поля остаются `null`; поисковые движки не сохраняют содержание профилей. Модуль «Страница в файл» сохраняет текст явно запрошенной страницы.
- Повтор временных ошибок создаёт дочернюю задачу с точным списком площадок. Исходная задача сохраняется. Недоступные после обновления площадки явно отражаются в ошибке.
- Общий начальный каталог содержит восемь реальных сервисов с официальными источниками и двумя языками. Для неизвестной площадки честно показывается отсутствие описания. Автоматически загружаются только одобренные администратором официальные источники каталога; страницы найденных профилей не используются как вход AI.
- Telegram получает обычные сообщения и документы; age шифрует выгрузку, но не превращает поиск в сквозное шифрование. Загруженные пользователем файлы нельзя отозвать.

## Проверки

Полная изолированная проверка с настоящими PostgreSQL, Redis, age и библиотеками движков (без Bot Token и платного AI):

```sh
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -f compose.test.yaml down
```

HTTP-проверки движков направлены **только на локальный fixture-сервер**. Telegram и DeepSeek в автоматических тестах заменены проверяемыми API-контрактами; тесты не сканируют людей и не расходуют платный API. CI запускает линтер, тесты с PostgreSQL и сборку обоих образов.

Фактические итоги полного прогона, реальные smoke всех шести модулей, измерения RSS и границы внешних интеграций — в [журнале проверки](docs/verification.md).

Локальная разработка:

```sh
uv sync --frozen --extra dev
uv run --frozen ruff check src engines tools tests scripts migrations
uv run --frozen pytest -q
```

Без `ECHO_TEST_LIVE_ENGINES=1`, `ECHO_TEST_TOOLS=1`, установленных native-окружений, PostgreSQL и age соответствующие интеграционные тесты пропускаются. Compose включает их. Для отдельного smoke модулей после сборки: `docker run --rm echo-bot:test pytest -q -s tests/test_tools_smoke.py`.
