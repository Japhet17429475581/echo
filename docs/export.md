# Отчёты и age

Экспорт не использует AI. Он включает текущее состояние задачи (включая незавершённую выдачу), ник, дату с часовым поясом, параметры, версии движков, исходные/нормализованные статусы, HTTP и доступные основания, описания площадок с источниками и происхождением, пользовательские отметки/заметки и предупреждение об ограничениях достоверности.

- **HTML**: один самостоятельный файл, мобильная вёрстка, локальный поиск и фильтры статуса/категории. Без CDN, загрузок, внешних шрифтов/картинок и трекеров; Jinja autoescape; ссылки допускают только HTTP(S). Открытие ссылки — явный переход во внешний сервис. JavaScript работает только с DOM отчёта и не выполняет сетевые запросы.
- **PDF**: ReportLab, встроенный Unicode-шрифт DejaVu Sans, переносы длинных строк, страницы и кликабельные ссылки. Без стороннего HTML. На локальном Windows для разработки можно указать путь к лицензированному кириллическому TTF через `ECHO_PDF_FONT`.
- **CSV**: UTF-8 BOM, одна строка на наблюдение движка. Опасные начальные `= + - @`, управляющие и маскирующие пробелы обезвреживаются префиксом `'`. Это намеренное изменение представления ради безопасного открытия в spreadsheet; исходные строки доступны в JSON.
- **JSON**: версия `echo.report/1`, явные публичные поля без секретов, внутренних путей, Telegram ID и текстов исключений. `null` означает отсутствие исходных данных, а не догадку.

Схема `echo.report/1` расширена необязательными полями: `coverage_summary`/`coverage_text`, `results[].false_positive_reason` и `results[].reviewed_at`. Статусы observations остаются исходными; личная отметка не превращает POSSIBLE_MATCH в NOT_FOUND. Причина, время, заметка и пояснение охвата отображаются в HTML/PDF и отдельных CSV-колонках; HTML фильтрует useful/false_positive отдельно от статусов движков. Неизвестный полный охват явно отмечается, ноль из известной части плана не означает полного покрытия.

Пакет выбранных карточек хранит каждую отдельным folder-item со снимком отчёта и `selection` (ключ выбранной карточки и размер исходной выдачи). Пояснение охвата относится к исходной задаче, а не к числу выбранных карточек. Повторное подтверждение одной подборки в ту же папку не создаёт дубликаты; при недостаточной вместимости запись целиком откатывается.

Проверка владельца выполняется до генерации и ещё раз перед доставкой. PDF и зашифрованные выгрузки выполняются очередью под общим тяжёлым слотом; PDF использует отдельный ограниченный процесс и временный scratch. Простые HTML/CSV/JSON формируются в памяти. Максимальная доставка 45 МиБ, queued экспорт и ZIP до 40 МиБ. При превышении выберите компактный формат или меньше материалов.

Модульные отчёты имеют схему `echo.module/1`; выдаются реальные поддержанные форматы (OCR TXT, страница TXT/MD/HTML, остальные JSON), а не пустые поисковые PDF. ZIP задач/папок содержит versioned `manifest.json`, исходные параметры без секретов, версии, дату/часовой пояс, размер и SHA-256 каждого материала. Внешний `.sha256` относится к итоговому ZIP либо ZIP.age; manifest не хэширует сам себя. Проверка хэшей не удостоверяет подлинность источника. Импорт архивов не реализован. Подробности и ограничения — [modules.md](modules.md).

## Получение зашифрованного файла

Создайте ключ **на своём устройстве** стандартной программой [age](https://age-encryption.org/):

```sh
age-keygen -o identity.txt
age-keygen -y identity.txt
```

Сохраните `identity.txt` в безопасном месте. В `/settings` бота передайте только публичную строку `age1…`. Echo поддерживает нативные X25519 recipients; SSH recipients и plugins сознательно не принимаются. Проверка checksum выполняется реальной age CLI, не самодельной криптографией.

После выбора зашифрованного формата бот показывает SHA256 от точной публичной строки. Этот fingerprint — идентификатор получателя для сверки в интерфейсе Echo; это не отдельный формат ключа age. Подтвердите его, затем получите `echo-xxxxxxxx.pdf.age` (либо другой формат). Изменение ключа делает старое подтверждение недействительным.

Расшифровка:

```sh
age --decrypt --identity identity.txt --output report.pdf echo-xxxxxxxx.pdf.age
```

Для HTML/JSON/CSV/ZIP используйте соответствующее расширение выходного файла. Не отправляйте приватный ключ боту. Сервер передаёт открытые байты в age через stdin; до шифрования PDF/ZIP могут существовать во временном scratch и память содержит plaintext. Нельзя обещать безопасное физическое стирание памяти/SSD или сквозное шифрование поиска: исходные данные обрабатываются сервером. Шифрование результата не скрывает сам факт взаимодействия с Telegram. Тест папок проверяет каждый SHA-256 manifest и полноценный ZIP.age decrypt round-trip.

Автоматический тест создаёт временную identity, шифрует Unicode-строку, расшифровывает стандартной age CLI и сравнивает байты. Он выполняется в тестовом Docker-образе, где age установлен из Debian.
