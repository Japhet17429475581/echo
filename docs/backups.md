# Резервное копирование и восстановление

Результаты приватны; не отправляйте незашифрованные backups в общедоступное хранилище. Ниже команды оператора для собственного развёртывания. Выполняйте их в защищённом каталоге; `backup.age` нельзя хранить вместе с приватной identity. В Windows PowerShell 5 текстовое перенаправление может повредить бинарный dump — выполняйте pipeline внутри Linux/WSL или контейнера.

Для внешней PostgreSQL используйте резервные копии провайдера либо штатные `pg_dump`/`pg_restore` с её подключением и SSL-настройками. Примеры ниже относятся к необязательному профилю **local-db** и выполняются в Linux/WSL:

```sh
docker compose --profile local-db exec -T postgres pg_dump -U echo -d echo -Fc | age -r age1YOUR_PUBLIC_RECIPIENT > echo-backup.dump.age
```

Сохраняйте `.env` отдельно в хранилище секретов. Redis AOF живёт в именованном volume: для согласованной копии остановите bot/worker и Redis, затем архивируйте volume инструментами оператора. Сохранение Redis важно для бюджетов: его сброс в течение суток может обнулить расходные ограничения. При потере Redis временно выключите AI до сверки с провайдером/следующих UTC-суток.

Загруженные файлы, артефакты и папки требуют также volume `files` (`/data/echo`). Для согласованного snapshot остановите bot/worker, сделайте dump PostgreSQL и зашифрованную копию volume штатными средствами оператора. Восстанавливайте БД и files из одной точки, с UID/GID 10001, каталогами 0700/файлами 0600. Без файловой копии метаданные БД не восстановят содержимое; чтение отсутствующего или изменённого файла будет отвергнуто. Не включайте `/tmp` в backup. Перед возобновлением выполните cleanup и повторно примените удаления также к файлам.

Рекомендованная политика для небольшого развёртывания: зашифрованные ежедневные копии, хранение не более 7 дней, отдельный защищённый журнал подтверждённых запросов удаления, ограниченный доступ оператора. Это рекомендация, а не автоматическая функция приложения: период и удаление copies настраивает оператор. Расписание удаления текущих результатов реализовано worker.

Восстановление в **новую** пустую БД после остановки приложения:

```sh
age -d -i identity.txt echo-backup.dump.age | docker compose --profile local-db exec -T postgres pg_restore -U echo -d echo --no-owner --no-privileges
docker compose run --rm migrate
docker compose run --rm worker python -m echo.main cleanup
```

Команда `pg_restore` предполагает подготовленную пустую БД и не удаляет старые таблицы. Не запускайте её вслепую поверх production. До включения bot/worker повторно примените запросы удаления, поступившие после даты backup, по защищённому журналу оператора. Само приложение не хранит идентификаторы удалённых пользователей в вечном tombstone.

Восстановленные lease истекут, сохранённые проверки не дублируются. Проверьте версии миграций и движков, состояние бюджета и список активных задач через агрегированное администрирование. Регулярно проводите восстановление копии в отдельной среде без настоящего Telegram token и с AI выключенным.
