# Хранение и приватность

Echo проверяет возможные совпадения публичного ника. Он не устанавливает личность и не извлекает дополнительные идентификаторы. Результаты разных пользователей не кэшируются совместно. Поиск не является секретным чатом Telegram.

## Что сохраняется

PostgreSQL: Telegram ID для владения, настройки, публичный age-ключ, задачи с ником, структурированные наблюдения движков, отметки и заметки. История выключена по умолчанию: результаты временные, TTL 6 часов. При включённой истории — 30 дней. Изменение настройки обновляет сроки существующих задач. Все сроки настраиваются; фоновая очистка удаляет просроченные данные.

Redis: краткие UI-состояния (draft, текущая задача, ввод заметки/ключа, подтверждения), распределённые интервалы, ограниченные AI-кэши без идентификаторов, бюджеты и счётчики со случайной generation вместо Telegram ID. UI-ключи находятся в пользовательском namespace и удаляются по запросу под блокировкой пользователя; старая generation не может записать их повторно. AI-учёт PostgreSQL содержит только тип операции, модель, попытки, время, usage/оценку и исход, без пользовательского содержимого. Для обновления прогресса bot хранит только краткие хэши в памяти.

Файловый volume хранит явно загруженные файлы, результаты OCR/метаданных/страниц и экспорты с владельцем, SHA-256 и TTL. Новые модули не отправляют файлы, EXIF, OCR, QR и папки в DeepSeek. `/account` показывает настройки, количество задач/папок и место без вымышленного баланса. В сводке EXIF чувствительные поля скрыты, но полный JSON/ZIP их содержит.

Временные subprocess-каталоги принадлежат отдельной задаче и очищаются при выходе; остатки упавших процессов удаляются по проверке недействующего lease, а не возраста. PDF/ZIP используют ограниченный plaintext scratch; age получает уже подготовленные байты через stdin. TTL доступа проверяется до физической очистки. Удаление файлов не объявляется гарантированным физическим стиранием SSD.

Рабочая папка — явное отдельное хранение, в том числе при выключенной истории: до 30 дней от создания по умолчанию. Сохранённые отчёты/артефакты копируются, поэтому удаление исходной задачи не удаляет выбранные материалы папки. Удалите материал/папку отдельно либо используйте `/delete_my_data`. TTL задач и папок может отличаться; настройка истории не включает папки автоматически.

Подборка карточек сохраняется только по явному выбору и целиком в одной транзакции. Карточки содержат снимок ваших заметок и отметок на момент сохранения; изменение исходной отметки позднее не переписывает копию. Причина ложного совпадения и время её установки хранятся в личной Annotation, не меняют Check и не отправляются площадкам или AI. Очистка отметки удаляет её причину/время.

Предложение открыть недавний результат использует только собственные доступные COMPLETED/PARTIAL задачи с теми же параметрами в пределах `ECHO_RECENT_RESULT_MINUTES` (30 минут). Это не общий кэш результатов разных пользователей. Истёкшие, удалённые, ошибочные и отменённые задачи не предлагаются. UI-состояния выбора цели/подборки/повтора находятся в прежнем пользовательском Redis namespace, защищены generation и удаляются вместе с данными.

## Удаление

`/delete_my_data` требует явного подтверждения и удаляет пользователя, задачи, проверки, аннотации, папки и его файлы, затем Redis namespace. `/tasks` также позволяет удалить одну задачу с подтверждением, включая её отдельные export-задачи. Другие задачи и явно сохранённые копии папок остаются. Каждый callback и экспорт проверяет владельца. Запись worker проходит через lease/generation и блокировку задачи, поэтому удаление не позволяет старому worker повторно создать результаты. Запущенные процессы завершаются после проверки heartbeat; их сохранения сразу отвергаются.

Публичный ключ можно убрать отдельно; AI и историю — выключить. Общий каталог площадок остаётся, поскольку не содержит поисковых идентификаторов. Обезличенная статистика и консервативные бюджетные резервы сохраняются на срок их учёта, чтобы удаление не создавало обход бюджета.

При выключении AI уже отправленный провайдеру запрос мог быть обработан и оплачен; новые запросы обогащения проверяют актуальную настройку. Удаление не отзывает уже переданные Telegram документы или локальные пользовательские копии. Отправка документа, уже начатая одновременно с удалением, может завершиться.

## Логи и резервные копии

Логи не включают Update, тексты сообщений, ники, профильные URL, заметки, отчёты, запросы AI, токены или DSN. Исключения преобразуются в фиксированные безопасные коды; SDK-логгеры отключены. Не включайте SQL echo/HTTP debug в production. Docker ограничивает ротацию логов.

Оператор отвечает за зашифрованные резервные копии и срок их удаления: рекомендован короткий документированный срок. Удаление из текущей БД не переписывает исторические копии; восстановление может вернуть старые данные, поэтому нужны короткая ретенция, журнал запросов удаления вне восстановленной БД и повторная очистка перед запуском. См. `backups.md`.
