# Инструменты ECHO и рабочие материалы

## Доступные сценарии

`/menu` открывает поиск, инструменты, папки, личный кабинет и настройки. `/tools` открывает шесть модулей. Выберите инструмент, отправьте ввод, проверьте параметры и подтвердите запуск. Неоднозначный файл получает список подходящих действий. Прогресс показывает этап и действительные счётчики; отдельная кнопка останавливает задачу. Результаты доступны также через `/tasks`.

| ID / меню | Реальная реализация и ввод | Результат | Таймаут / память процесса |
|---|---|---|---|
| `metadata` / Метаданные файла | ExifTool 12.57 + libmagic; оригинал документом, JPEG/PNG/WebP/TIFF/GIF/PDF/MP3/WAV/MP4 по реальному MIME | Сводка, все поля, отдельно чувствительные поля, исходные даты/offset, JSON; очистка только JPEG/PNG | 30 с / 384 МиБ |
| `ocr` / Текст с изображения | Tesseract 5.3.0, rus/eng/rus+eng; JPEG/PNG/одно изображение WebP | Неисправленный текст, копируемые фрагменты, TXT и JSON | 90 с / 768 МиБ |
| `qr` / Прочитать QR | zxing-cpp 3.1.1 + Pillow 13.0.0; JPEG/PNG/одно изображение WebP | Все найденные QR (не более 64), тип, текст, домен, исходные байты base64 в JSON | 30 с / 384 МиБ |
| `passport` / Паспорт сайта | Защищённый HTTP fetch, WhatWeb 0.5.5, dnspython 2.9.2, стандартный проверяемый TLS | HTTP/redirects, ASCII/IDN, сертификат, DNS A/AAAA/MX/NS/TXT, признаки технологий с основаниями, JSON | 60 с / 512 МиБ |
| `page` / Страница в файл | Защищённый fetch одной страницы + Trafilatura 2.3.1 | Заголовок, текст, исходный/конечный URL, время, непроверенные автор/дата, TXT/MD/HTML/JSON | 45 с / 512 МиБ |
| `domains` / Похожие домены | dnstwist 20250130 только Fuzzer + отдельный ограниченный DNS | Варианты, преобразования, DNS и статусы, JSON; только после подтверждения прав | 120 с / 512 МиБ |

Версии системных пакетов относятся к проверенной сборке Debian Bookworm. APT получает обновления при новой сборке; точные версии записываются в результат и проверяются командами ниже. Python lock-файлы фиксируют версии и SHA-256. Linux amd64 проверен фактически; arm64 предусмотрен изоляцией, но в этой среде не проверялся.

Каждый модуль имеет `ECHO_<ID>_ENABLED`, `ECHO_<ID>_TIMEOUT`, `ECHO_<ID>_MEMORY_MB`, контракт `Module` в `modules.py`, проверку ввода, schema `echo.module/1`, артефакты и общий lifecycle. Бинарники проверяет worker при старте, публикуя capabilities с TTL. Без зависимости, языкового пакета или kernel isolation модуль недоступен; остальные доступные функции продолжают работать. Тяжёлые библиотеки загружаются в `/opt/tools`, не в Telegram handlers. После установки зависимости перезапустите worker.

## Ограничения результатов

Для OCR/QR/очистки — максимум 8 000 000 пикселей, один кадр, файл до 10 МиБ. PDF OCR и анимация не поддержаны. Pillow проверяет формат, декодирование и decompression bombs. Результат native JSON не более 512 КиБ. Лимит не обещает распознавание всех QR или безошибочный OCR. Текст не отправляется AI; копирование управляющих символов показывает их экранированное представление, исходные байты QR остаются в JSON.

Очистка применяет EXIF orientation к пикселям и повторно кодирует JPEG/PNG, удаляя EXIF/GPS/XMP/IPTC/комментарии/ICC. Копия повторно открывается, проверяются размеры, ориентация и отсутствие заявленных полей через ExifTool. Остаются технические свойства формата, кодирования и пикселей; JPEG перекодируется с quality 95, ICC не сохраняется, поэтому цвет может измениться. Оригинал не меняется. **JSON и ZIP отчёта содержат метаданные оригинала**; для передачи только очищенного изображения выбирайте `cleaned.jpg`/`cleaned.png`. Это не полная анонимизация: содержание пикселей, стеганография и происхождение изображения не проверяются. Поля устройства/дат могут отсутствовать или быть изменены; чувствительные поля выводятся отдельно только владельцу в личном чате.

QR не вызывает внешних сервисов. Кнопка открытия появляется только для синтаксически допустимого HTTP(S); она не подтверждает надёжность сайта. `javascript:`, команды, Wi-Fi и контакты остаются текстом. Адрес не загружается при декодировании.

WhatWeb получает **локальную сохранённую страницу**, `--aggression=1 --max-threads=1 --log-json=...`. Его собственная сеть запрещена ядром: никакой повторной загрузки, перебора путей или агрессивных запросов. Технология — основание предположения, не гарантированный факт. Сохраняется ограниченный набор plugin evidence без внутренних путей. TLS проверяет системную цепочку, hostname и SNI; ошибка соединения/сертификата показана как отсутствие подтверждённого TLS. DNS-ответы могут содержать внутренние IP, но это не разрешает HTTP по ним. Сертификат проверяется для исходного домена; цепочка HTTP содержит конечный адрес отдельно.

Trafilatura получает один ограниченный HTML-ответ; скрипты и дополнительные ресурсы не исполняются. Автор/дата имеют явное происхождение и не считаются проверенными. TXT/MD содержат извлечённый текст; standalone HTML экранирован, без ресурсов и скриптов, с CSP. Это не точная архивная копия. Paywall, CAPTCHA и авторизация не обходятся. Похожесть доменов не означает фишинг; dnstwist не делает HTTP, screenshots, MX-письма или активные проверки вариантов.

## Единая очередь и профили

Все виды задач используют существующий PostgreSQL Job, admission gate, владение, generation, lease/fencing, отмену и TTL. Redis ZSET выдаёт один deployment-wide тяжёлый слот eco; TTL продлевается heartbeat. Потеря аренды/Redis отменяет выполняющуюся задачу; после падения аренды истекают, очередь возобновляет работу. Просроченный слот не продлевается заново. PDF, ZIP, age и модули используют тот же слот, без повторного захвата вложенной подзадачей. Telegram handlers, прогресс и отмена слот не занимают. Один worker последовательно обрабатывает свою очередь; два слота standard требуют двух workers для двух параллельных задач.

| Параметр | eco (`compose.yaml`) | standard (добавить `compose.standard.yaml`) |
|---|---|---|
| RUNNING / тяжёлые слоты на deployment | 1 / 1 | 3 / 2, лишний RUNNING ожидает слот |
| QUEUED + RUNNING на пользователя | 1 | 2 |
| Глобальная очередь / задач на пользователя в сутки | 100 / 20 | 100 / 20 |
| Sherlock + Maigret | Последовательно | Последовательно по умолчанию |
| OCR OpenMP | `OMP_THREAD_LIMIT=1`, `OMP_NUM_THREADS=1` | 1, можно явно изменить до 4 |
| HTTP соединения / таймаут запроса | 2 / 10 с | 2 / 10 с |
| HTTP body / headers / redirects | 1 000 000 байт / 32 КиБ / 3 | Те же |
| dnstwist варианты / DNS-вызовы A/AAAA | 25 / 50 | Те же; можно снизить перед запуском |
| DNS таймаут / записей на тип | 2 с / 8 | Те же |
| Файловый volume / пользователь / scratch одной задачи | 256 / 64 / 64 МиБ | 1024 / 64 / 64 МиБ |
| Минимум свободного места | 64 МиБ | 64 МиБ |
| Экспорт / память / время | 40 МиБ / 768 МиБ / 120 с | Те же |

Профиль eco валидирует одну активную задачу/слот, одного пользователя, последовательные движки и один OCR thread. Для ручного изменения этих ограничений установите `ECHO_RESOURCE_PROFILE=standard` одновременно в bot и worker. Все параметры и допустимые границы — в [configuration.md](configuration.md). `DOMAIN_INTERVAL` через Redis применяется к точному HTTP hostname перед каждым запросом, в том числе redirect; DNS выполняется последовательно, без массового параллелизма и в отдельном жёстком бюджете. Возврат NXDOMAIN, NO_ANSWER, TIMEOUT и DNS_ERROR различается.

Пределы памяти контейнеров eco: worker 1280 + bot 384 + PostgreSQL 384 + Redis 192 = **2240 МиБ**, плюс ОС, Docker и запас; `migrate` 512 МиБ выполняется до запуска приложений. Рекомендуемая стартовая машина — 4 ГБ RAM. Standard: с двумя workers 4096 + 384 + 512 + 256 = **5248 МиБ**, ориентир 8 ГБ RAM. Это бюджеты, не замеры постоянного потребления и не обещания пропускной способности. У Docker Desktop память VM входит в бюджет хоста. Не запускайте стек на 1 ГБ по этим настройкам; swap не заменяет RAM. Для каждого дополнительного worker пересчитайте бюджет.

Native subprocess получает RLIMIT_AS, CPU (90 с на процесс), FSIZE, NOFILE, watcher RSS/числа процессов/диска каждые 100 мс, wall timeout и ограниченный stdout. Дочерние процессы получают минимальное окружение, отдельную группу и parent-death signal; отмена завершает всё дерево. Число процессов 16 — предел watcher дерева одной задачи, дополнительно контейнер ограничен 192 PID. Дисковый watcher не является мгновенной файловой квотой ядра; tmpfs 128 МиБ и лимит файла ограничивают последствия коротких пиков. Cgroup/container лимит — последняя граница всего worker.

## Изоляция и хранение

Локальные обработчики защищены Landlock и seccomp, требуются kernel ABI ≥3 и libseccomp. Им доступны scratch и разрешённые библиотеки/системные данные, но не файловый volume, `.env`, `/proc/*/environ` и секреты других процессов. `socket/connect/socketpair`, ptrace и обходные системные вызовы запрещены; проверка изоляции fail-closed. Это проверяется настоящими системными вызовами в smoke. ЧтоWeb получает HTML только через родительский защищённый fetch; CLI не может обойти SSRF-политику.

SafeNetwork нормализует публичный HTTP(S), запрещает служебные IPv4/IPv6, credentials, нестандартные порты, проверяет все DNS-адреса и каждый redirect, передаёт проверенные IP connector напрямую. Cookies, authorization, ambient proxy и сжатые ответы отключены; количество/размер заголовков и тело ограничены, TLS проверяется. Нет общедоступного proxy endpoint. Для внешнего egress firewall оставляйте PostgreSQL/Redis доступны только приложению; native обработчики сети не имеют.

`ECHO_DATA_DIR=/data/echo` — общий именованный volume bot/worker, opaque UUID filenames, права файлов 0600/каталогов 0700. Имена пользователя используются только как очищенные подписи. Квоты резервируются транзакционно до потоковой загрузки, SHA-256 проверяется перед чтением/скачиванием. Файловая задача не принимается при нехватке места. Временные каталоги случайные, связаны с Job lease; остатки удаляются после проверки, что lease больше не действует, а не только по возрасту. TTL действующей задачи вызывает отмену; её файлы не стираются из-под процесса до окончания аренды.

## Папки, сравнение и экспорт

`/folders` → создать → добавить заметку/файл/отчёт или «Сохранить в папку» в результате. Поддержаны переименование, удаление материала/папки и ZIP/age. На пользователя до 10 папок, по 50 материалов; TTL папки 30 дней от создания. При выключенной истории интерфейс объясняет, что папка — явное отдельное хранение. Добавление отчёта копирует артефакты: удаление исходной задачи не стирает сохранённую папку. Удаление папки или всех данных удаляет эти копии. Автоматического связывания людей нет.

«Сравнить» или `/compare`: две собственные завершённые/частичные задачи одного типа и цели, ручное подтверждение прав. Учитываются версии движков, параметры, покрытие и даты; разный охват отмечается отдельно. TIMEOUT/BLOCKED/NOT_FOUND не превращаются в «аккаунт удалён». Вывод JSON содержит новые, изменённые, неизменившиеся и не проверенные во второй задаче элементы. Автоматического наблюдения нет.

ZIP содержит материалы и `manifest.json` версии `echo.package/1`, схемы/версии инструментов/параметры/время/часовой пояс и SHA-256 каждого материала. Сам manifest не может содержать свой собственный SHA-256: рядом с итоговым ZIP/ZIP.age выдаётся внешний `archive.sha256` после упаковки/шифрования. Контрольная сумма обнаруживает изменение байтов, не удостоверяет источник. Имена внутри пакета формируются сервером; импорт и распаковка входящих архивов не реализованы. Суммарный несжатый и итоговый размер до 40 МиБ, Telegram delivery до 45 МиБ с учётом age. При превышении удалите лишние материалы и повторите экспорт. ZIP/PDF строятся в изолированном subprocess под общим слотом; plaintext scratch удаляется после обработки, физическое стирание не обещается.

## Диагностика и обновление

`docker compose exec worker python -m echo.main admin` выдаёт полные агрегаты, включая retained задачи по типу/состоянию, ошибки/таймауты/отмены/лимиты, длительность/ожидание, байты, sampled CPU/RSS, свободный диск и доступные модули. `/admin` показывает укороченный JSON. Нет публичных labels по Telegram ID, никам и доменам. Метрики относятся к сохранённым задачам и исчезают с TTL/удалением; это не вечный мониторинг. RSS — сумма RSS дерева процессов по выборкам 100 мс (общие страницы могут учитываться повторно, короткие пики пропускаться), не память сервера. CPU sampled также может пропускать короткоживущие процессы. Фактические измерения — [verification.md](verification.md).

Проверка зависимостей/версий:

```sh
docker compose exec worker exiftool -ver
docker compose exec worker tesseract --version
docker compose exec worker tesseract --list-langs
docker compose exec worker whatweb --version
docker compose exec worker uv pip list --python /opt/tools/bin/python
```

Для обновления меняйте точные версии в `tools/requirements.in`, выполните `uv pip compile tools/requirements.in --generate-hashes --universal -o tools/requirements.lock`; для основного dnspython — правку `pyproject.toml` и `uv lock`. Пересоберите без APT cache (`docker compose build --no-cache`), проверьте версии и лицензии, затем полный `compose.test.yaml`. Только после успешного smoke пересоздайте bot/worker. Не подменяйте отдельный бинарник в уже работающем контейнере.

Полный воспроизводимый прогон без Telegram token и платного AI:

```sh
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -f compose.test.yaml down
```

Файлы OCR/QR/EXIF генерируются локально `tests/make_tool_fixtures.py`, HTTP/TLS — локальные fixtures, DNS вариантов — mock; внешние люди/случайные домены не сканируются. Native smoke проходят реальные Telegram handlers через aiogram Dispatcher и локальную Bot API session. Настоящий Telegram и DeepSeek требуют отдельно выданных оператором ключей и живого smoke; автоматические тесты не заменяют эту проверку.
